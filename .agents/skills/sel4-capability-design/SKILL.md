# sel4-capability-design（保護ドメインと capability の設計）

## 原則

- 部品は保護ドメイン（独立した VSpace・CSpace・thread を持つ単位）に分けます。driver は device ごとに 1 つの保護ドメインにし、利用者向けの機能と分けます。
- システムは静的に記述し、起動時に初期化部品（capDL loader など）が全 capability を配ります。初期化の後に、権限を増やす部品や、untyped memory から任意の object を作れる部品を作りません。例外が必要なら、理由と範囲を書き、利用者の判断を得ます。
- 各部品には、動作に必要な capability だけを渡します（最小権限）。書き込みの権限、device のメモリ、割り込み、他の部品への endpoint は、必要な部品だけに渡します。
- 部品の間のデータは、方向が決まった共有メモリの queue と通知で渡し、受け取る側で長さと内容を検査します。

## 設計の手順

1. 機能ごとに、扱うデータ、信頼の前提、障害時の影響を書きます。
2. 保護ドメインの一覧を作り、各ドメインの役割、優先度、予算、扱うデータを書きます。
3. capability の表を作ります。列は「保護ドメイン」「対象（endpoint、notification、共有メモリ、device のメモリ、IRQ、untyped など）」「権限（読み・書き・実行・grant など）」「理由」です。
4. DMA を使う device（SDHOST/SDHCI、USB、DMA controller など）の driver は、IOMMU がないため全メモリに書ける部品として扱い、表に明記します。DMA の対象を限る方法（専用の領域、検証した descriptor の作り方）を書きます。
5. capDL などの記述と表を照合する検査を用意し、CI で表と記述の一致を確かめます。
6. 障害の影響を確かめます。1 つの部品が止まった・暴走したとき、ほかの部品と永続データに何が起きるかを書き、復帰の方法（再起動する部品、監視する部品）を決めます。

## 提出前の確認

- [ ] 全保護ドメインと capability が表にあり、記述と一致する
- [ ] 各 capability に理由がある
- [ ] DMA を使う部品を明記した
- [ ] 実行時に権限を増やす部品がない（例外は判断の記録がある）
- [ ] 部品の障害の影響と復帰の方法を書いた
